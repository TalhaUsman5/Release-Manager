The two real defects the classifiers caught

arbiter → test_gap → verify build attempt 1
“The failing assertions incorrectly require HTTP 200 for deliberately configured nonzero subprocess exit codes (Reject exit 27 and Scan exit 23). The implementation correctly preserves established result handling by treating nonzero CLI exits as failed process results and returning HTTP 500 … The test therefore rejects the intended scenario before checking the presentation behavior it claims to cover.”
review_arbiter → implementation_gap → build review rejection, final pass
“The status indicator falsely reports an empty audit history when activity data cannot be read due to permission or other I/O failures. That is misleading recent-activity visibility and violates the request's usability goal as well as the contract's non-misleading empty-state requirement. A genuine absence of an audit file may be shown as no activity, but operational read failures require a distinct unavailable/error state.”
